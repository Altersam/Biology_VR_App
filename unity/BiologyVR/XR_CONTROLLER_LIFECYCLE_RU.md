# XR-контроллеры: режимы, анимация, направляющие и UI

Рабочий проект `bio_v0.2`, 11 октября 2026.

## Исправленная логика

- `JourneyInput` каждый кадр читает актуальное нажатие из включённого InputAction.
  Подписки на callbacks сохраняются, но не служат единственным источником
  состояния удержания. На физическом XR есть fallback чтения Trigger устройства.
- Наведение на UI без нажатия не отключает инструменты. При нажатии над
  видимой интерактивной панелью блокируется только соответствующая рука.
  Другая рука продолжает работать; компонент ввода остаётся включённым.
- Нажатие, начавшееся на UI, не превращается в выстрел при уходе луча с панели.
  Отпускание и новое нажатие сразу возвращают работу прибора. Причина блокировки
  выводится в feedback; направляющая этой руки становится янтарной.
- Невидимые/отключённые Canvas и неинтерактивные CanvasGroup не перехватывают ввод.
- UI проверяется в LateUpdate после обновления позы руки; новое нажатие больше
  не блокируется из-за наведения на панель в предыдущем кадре. Биологический
  контакт перед панелью также имеет приоритет перед её геометрической плоскостью.
- Две тонкие XR-направляющие существуют независимо от Trigger, текущей задачи,
  попадания и короткоживущих эффектов. Луч следует aim-transform прибора,
  заканчивается на ближайшем подходящем контакте/препятствии либо на 12 м.
- Каждая смена режима запускает явную короткую анимацию короны/корпуса,
  подсветку и индикатор. Это относится к правым A/B и автоматическому
  рекомендуемому режиму при смене задачи.
- Каждое новое удержание Trigger запускает короткую реакцию модели, даже при
  промахе либо неверном режиме. Удержание продолжает режимную анимацию.
  TONUS/BIO поле видно также без контакта; успех задачи всё равно требует
  правильного действия и цели. CAPTURE сохраняет захват/направляющие отдельно.

Управление: левый Trigger — Scanner; правый Trigger — BioTool;
правая A — следующий режим, B — предыдущий; левая Y — Continue; Grip — XRI.
